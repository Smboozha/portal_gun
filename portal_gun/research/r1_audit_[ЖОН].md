## 1. Диагноз float-бага (подтверждён независимым trace)

**Место:** `_worm_num()` в `wormhole_ft_derive.py:189–204`.

**Корень (двухступенчатый):**

### 1a. Подстановки выполняются в НЕВЕРНОМ порядке
В `_worm_num`:
```python
e = expr.subs({r: rv, b0: bv, th: thn})   # СТРОКА 199: r заменён числом ПЕРВЫМ
...
e = e.subs(A, 1).subs(B, Bn).subs(C, rv)  # СТРОКА 202: A=Function('A')(r)
```
Поскольку `A = sp.Function('A')(r)`, то после замены `r -> 0.2` все вхождения `A(r)` превращаются в `A(0.2)` = `Function('A')(Float(0.2))`. Оригинальный объект `A` (= `Function('A')(r)`, с **символом** `r`) в выражении **больше не встречается**, поэтому `subs(A, 1)` ровно ничего не делает.

**Проверка (минимальный репро, sympy 1.14):**
```
r=Symbol('r'); e=A**2; e2=e.subs(r, 0.2) -> A(0.2)**2
e2.subs(A, 1) -> A(0.2)**2   (НЕ меняется!)
```

### 1b. Почему падает именно `Cannot convert to float`
`evalf(30)` сам по себе **не бросает** — он возвращает символьное выражение, внутри которого остались `A(0.2), B(0.2), C(0.2)` (неопределённые функции). Бросает обёртка на строке 204:
```python
return complex(e.evalf(30))
```
`complex(...)` от выражения, содержащего `A(0.2)`, даёт `TypeError: Cannot convert expression to float`.

**Trace `r3_debug_worm_num.py` это наглядно показывает:**
```
после A,B,C + doit  free=[]  funcs=['A', 'B', 'C']   # функцкии ОСТАЛИСЬ, r нет
EVALF = (-A(0.2)**2*B(0.2)**2 + ...)/(A(0.2)**4*...) # символьное, не число
```
Функции `A,B,C` не заменены → `funcs` не пуст → `complex()` падает.

## 2. Исправление (точечная правка — подтверждённое)

Исправление: подставлять **значения функций до** замены координат, а `r,b0,θ` — **в самом конце**:

```python
def _worm_num(expr, rv, bv, thv=None):
    thn = thv if thv is not None else sp.pi/4
    db = 1 - bv**2/rv**2
    dbp = 2*bv**2/rv**3
    dbpp = -6*bv**2/rv**4
    Bn = db**-0.5
    Bpn = 0.5*db**-1.5*dbp
    Bppn = -0.75*db**-2.5*dbp**2 + 0.5*db**-1.5*dbpp
    e = expr
    # СНАЧАЛА производные (r ещё символ — совпадение по форме работает)
    e = e.subs(A.diff(r, 2), 0).subs(B.diff(r, 2), Bppn).subs(C.diff(r, 2), 0)
    e = e.subs(A.diff(r), 0).subs(B.diff(r), Bpn).subs(C.diff(r), 1)
    # ЗАТЕМ сами функции (r ещё символ)
    e = e.subs(A, 1).subs(B, Bn).subs(C, r).doit()
    # ПОСЛЕДНИМ — численные координаты
    e = e.subs({r: rv, b0: bv, th: thn})
    return complex(e.evalf(30))
```
(Ключевой перенос строки `expr.subs({r:rv,...})` с начала — в конец.)

Это исправление соответствует диагнозу [ТР3], который я подтвердил независимым trace в `/tmp`-копии, и работает (все три EL дают числа, см. §3).

> Указание [ОСН]: на всякий случай сохранить `thn` как `sp.pi/4` (не float) до финальной подстановки — см. §3 прим. по QNM-точности.

## 3. ВАЖНОЕ СЛЕДСТВИЕ: GR-проверка после исправления НЕ СХОДИТСЯ ⚠️

После починки подстановок численный тест `EL(0) vs G_μν` при `r=0.2, b0=0.1` даёт:

| компонента | EL (f→0) | G_μν (Риччи) | ratio |
|-----------|----------|--------------|-------|
| A (00)    | 0.0      | +1.906e+02   | 0     |
| B (11)    | −4.0     | +2.083e+01   | −0.192|
| C (22)    | +1.155e+01| −1.125e+00  | −10.26|

**Три разных отношения — TEGR-уравнения при f=0 НЕ совпадают с GR-тензором в текущей нормировке/идентификации компонент.**

Это НЕ «округление» и НЕ остаточный символ — после починки всё чисто численное. Значит одно из двух:
1. **Способ сопоставления EL → G_μν некорректен**: EL — это уравнения по скалярным степеням {A,B,C}, а G_μν — компоненты тензора; между ними нужна корректная плотность/поднятие/нормировка `κ` и правильное отождествление, к-рое в текущем коде (`EL0/Gval` побайтно) заложено наивно.
2. **Реальная ошибка построения T или EL** (например, в суперпотенциале/конторсии), дающая неверные уравнения даже на диагональной тетраде.

> Правило проекта: **расхождение цифр = СТОП на разбор, а не округление.** Поэтому объявляю GR-сверку R1 **ОТКРЫТОЙ**, пока [ОСН] не проведёт нормировочный разбор (см. §4). Баг float закрыт, но «зелёная» сверка — НЕТ.

Замечание к точности: EL[A]=0 и выбор `Bppn*0` — сомнительная маскировка (см. §4.2).
